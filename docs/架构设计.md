# 回脉 · 架构设计文档

> **产品定位**：回脉是以伊斯兰价值观为精神内核、家庭友好、知识导向、内容合规（Halal）的**通用短视频平台**。伊斯兰是内核与内容审核依据，而非内容边界——平台内容多元，伊斯兰伦理用于对所有内容一视同仁地审核把关。

## 二、分层与包结构

后端采用按业务模块划分的包结构，每个模块内部再按职责分层，便于横向扩展：

```
com.huimai
├── common        # Result/PageResult/ResultCode、BusinessException、全局异常、BaseEntity
├── config        # Security、Redis、MyBatis-Plus、WebMvc、初始化器、配置属性
├── security      # JwtUtil、JwtAuthenticationFilter、LoginUser、SecurityUtils
└── module
    ├── user          # 注册、登录、资料
    ├── video         # 视频、分类、标签、内容来源
    ├── interaction   # 点赞、收藏、评论、关注
    └── file          # FileStorageService（存储/探测/封面）
```

- **统一返回**：所有接口返回 `Result<T>`（code/message/data），分页用 `PageResult<T>`
- **统一异常**：业务层抛 `BusinessException`，`GlobalExceptionHandler` 统一转换，保证错误结构一致
- **自动填充**：`MyMetaObjectHandler` 自动写入 created_at / updated_at / deleted
- **逻辑删除**：MyBatis-Plus `@TableLogic`，删除仅置标记，不物理删除

## 三、数据库设计

共 13 张表，按领域分为四组：

| 领域 | 表 | 说明 |
|---|---|---|
| 用户 | app_user、user_follow | 用户信息与关注关系（含冗余计数） |
| 内容 | video、category、tag、video_tag、content_source | 视频、频道、标签与内容来源 |
| 互动 | video_like、favorite、comment | 点赞、收藏、两级评论 |
| 系统 | play_log、report、notification | 播放分析、举报、通知 |

设计要点：

1. **冗余计数**：video 表内维护 like/comment/favorite/play 计数，app_user 维护粉丝/关注/作品数，避免高频 COUNT，计数变更用 SQL 原子自增（`setSql("x = x + 1")`）
2. **唯一约束**：点赞、收藏、关注均设联合唯一索引，保证幂等，切换逻辑先查后增删
3. **内容来源独立表**：content_source 与 video 一对多，source_type 区分 quran/hadith/other，可标注经典、文献、官方资料等权威出处
4. **评论两级结构**：parent_id=0 为一级，回复挂在其下，一级评论冗余 reply_count

## 四、视频处理流程

```
上传 MultipartFile
      │
      ▼
生成唯一文件名（UUID + 扩展名），按 yyyyMM 分目录
      │
      ▼
写入 storage/video/yyyyMM/
      │
      ▼
检测 FFmpeg（配置路径 → PATH，结果缓存）
      ├── 可用：ffprobe 探测时长/宽高，ffmpeg 截封面到 storage/cover
      └── 不可用：优雅降级，仅存储，时长/封面留空
      │
      ▼
写入 video 记录（status=1 已发布），处理标签与内容来源
      │
      ▼
作者 video_count +1，返回 VideoVO
```

- 媒体文件通过 `WebMvcConfig` 映射 `/media/**` 到 storage 根目录，结合 context-path 形成 `/api/media/...` 访问路径
- 前端开发由 Vite 代理 `/api` 到后端 9090，避免跨域与混合内容问题
- 升级路径：接入 FFmpeg 后自动启用封面与媒体信息；接入云点播时仅需替换存储服务实现，上层接口不变

## 五、安全设计

- **无状态 JWT**：登录成功签发令牌，后续请求在 `Authorization: Bearer` 头携带
- **过滤器**：`JwtAuthenticationFilter` 解析令牌并将 `LoginUser` 写入 SecurityContext
- **白名单**：登录注册、媒体资源、信息流与详情、接口文档可匿名访问，其余需认证
- **密码加密**：BCrypt 单向哈希，不明文存储
- **统一 401/403**：认证入口点与访问拒绝处理器直接返回 JSON 形式的 Result
- **前端守卫**：路由层拦截未登录请求，响应拦截器统一处理 401 并跳登录

## 六、缓存与计数

当前阶段以数据库为权威源，Redis 已就绪并完成 JSON 序列化配置，后续承担：

- Feed 流缓存与下拉分页
- 热点视频、分类、计数的读写缓存
- 礼拜时间、朝向等计算结果缓存
- 通知未读数、限流等

## 七、扩展规划

1. **推荐 Feed**：从时间线升级为标签 + 热度 + 关注的混合推荐，Redis 维护候选集
2. **转码与云存储**：FFmpeg 多清晰度（HLS）、阿里云 OSS/VOD，接口面向抽象存储
3. **内容审核**：人工审核流 + AI 审核接口（关键词/图像/语音），视频先入库为待审状态
4. **穆斯林友好能力**：基于地理位置的礼拜时间与朝向、斋月模式、希吉来历、阿中双语（特色服务，非使用门槛）
5. **管理后台**：独立 Element Plus 端，审核、举报、用户、数据看板
6. **容器化**：Docker Compose 编排 Nginx + 后端 + MySQL + Redis，便于交付部署
